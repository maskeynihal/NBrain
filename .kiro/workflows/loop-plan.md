# Loop Plan: Specify and Decompose

1. Read the discovery brief and inspect relevant code paths.
2. Draft requirements and acceptance criteria that are observable and testable.
3. Describe UX/API/data changes, technical approach, security/privacy concerns, migrations, observability, and failure modes as applicable.
4. Record significant decisions as ADRs and list rejected alternatives briefly.
5. Review the spec adversarially for ambiguity, missing edge cases, scope creep, and untestable criteria.
6. Break approved work into small tickets with dependencies, acceptance criteria, and verification steps.
7. Identify open questions and request user decisions where needed.
8. Save artifacts under the project's established documentation conventions; do not silently start implementation while key decisions remain unresolved.
