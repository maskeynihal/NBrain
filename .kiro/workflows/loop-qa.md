# Loop QA: Adversarial Verification

1. Read the approved specification and ticket acceptance criteria before reviewing implementation.
2. Inspect the diff and trace each changed behavior to its requirements.
3. Run relevant automated tests, type checks, linting, and build checks where available.
4. Probe edge cases, invalid inputs, permission boundaries, concurrency, failure recovery, accessibility, and regressions as relevant.
5. Separate confirmed defects from risks and speculative concerns.
6. For each finding, include severity, reproduction/evidence, expected behavior, actual behavior, and a proposed next step.
7. Fix in-scope defects or create actionable tickets; rerun checks after changes.
8. Report exact commands and actual results. Never imply unrun checks passed.
