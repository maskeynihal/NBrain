# Loop Implement: Deliver an Approved Ticket

1. Read repository instructions, the approved spec, the ticket, and relevant code/tests.
2. Confirm the ticket's scope and acceptance criteria; identify blockers before editing.
3. Implement the smallest coherent change consistent with local conventions.
4. Add or update tests for expected behavior, boundaries, and failure paths.
5. Update docs, schemas, configuration examples, or migration guidance where behavior changes.
6. Run targeted checks, then broader relevant checks if practical.
7. Review the diff for accidental scope, secrets, debug code, backwards-compatibility risks, and missing coverage.
8. Report changed files, decisions, commands run, exact results, and remaining concerns.
9. Do not claim the ticket is complete if acceptance criteria lack evidence.
