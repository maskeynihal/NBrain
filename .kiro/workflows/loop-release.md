# Loop Release: Evidence-Based Gate

1. Map each acceptance criterion to implementation and verification evidence.
2. List each test, lint, type-check, and build command actually run with its actual outcome.
3. Distinguish passed, failed, skipped, and not-run checks.
4. Summarize QA findings and confirm whether critical/high-severity issues remain.
5. Document known limitations, operational monitoring, security/privacy concerns, and rollback considerations.
6. Include required migrations, configuration changes, deployment order, and user-facing release notes.
7. State a clear recommendation: ready, ready with explicit risks, or blocked.
8. Never infer a successful release or deployment from a successful local test run.
