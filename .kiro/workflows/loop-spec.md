# Loop Spec: Write and Challenge the Specification

1. Read the discovery brief, user constraints, repository guidance, and relevant implementation.
2. Define the problem, goals, non-goals, personas or actors, and success measures.
3. Write functional and non-functional requirements with testable acceptance criteria.
4. Describe UX/API/data behavior, error states, authorization, privacy/security, observability, compatibility, and migration concerns as applicable.
5. List assumptions, dependencies, risks, and unresolved decisions.
6. Propose a technical approach and briefly consider viable alternatives.
7. Record consequential decisions in an ADR.
8. Review for contradictions, ambiguity, missing edge cases, scope creep, and criteria that cannot be verified.
9. Ask the user to decide material trade-offs. Do not treat assumptions as approved requirements.
10. Save the spec and test strategy using existing repository conventions.
